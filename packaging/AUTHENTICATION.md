# 本地鉴权与凭据流转

当前应用是可信本机上的个人模型网关，没有用户注册、登录会话、OAuth 或多用户权限体系。

## 组件和请求流程

1. `backend/app.py` 的 `lifespan` 初始化 SQLite；首次启动生成 `sk-local-` 加随机字符串的本地客户端 Key，写入数据目录的 `client.key`，已有 Key 不覆盖。
2. 下游客户端调用 `/v1/models`、`/v1/chat/completions` 或 `/v1/messages`。`require_client_key` 使用 `secrets.compare_digest` 比较传入值与本地 Key，失败返回 HTTP 401。
3. OpenAI 路径读取 Authorization；Anthropic 路径优先读取 `x-api-key`，没有时回退 Authorization。当前校验实现去掉可选的 `Bearer ` 前缀，因此也接受 Authorization 中直接传入 Key；它不是严格的 Bearer 格式解析器。
4. 校验通过后，路由层按逻辑模型选择部署，`choose_credential` 从可用上游凭据中轮转选择。上游凭据与本地客户端 Key 相互独立。
5. `forward` / `forward_stream` 向 Anthropic 写入 `x-api-key`，向 OpenAI / Responses 写入 `Authorization: Bearer …`。下游传入的本地 Key 不作为上游密钥透传。

## 应用内部管理令牌

- 桌面端每次启动后端时生成独立随机管理令牌，通过继承的私有 stdin 管道首行交给后端。令牌只保存在桌面进程、管理界面和后端内存中，不写入数据库、配置文件或日志，不在界面展示，也无需用户填写。
- 管理界面通过 Tauri IPC 获取当前后端的令牌，并在所有 `/api/*` 请求中附带 `X-Management-Token`。`/api/bootstrap` 同样受保护，不返回管理令牌。实时日志使用携带该请求头的 fetch 流，不把令牌放进查询参数。
- 后端先验证管理令牌，再处理管理请求；缺少、错误、重复令牌头均返回 HTTP 401。客户端 Key 和管理令牌不能互相替代。CORS 预检允许管理认证头，但不授予管理权限。
- 重启后端（包括启动失败后的重试）会生成新令牌，旧令牌立即失效；用户已有的 `client.key` 保持不变。桌面端不复用端口上已有的未知后端，避免误用其他实例的管理凭据。
- `/health` 继续用于无需令牌的实例健康检查，不返回任何密钥。管道首行之后的输入或 EOF 仍用于关闭后端。

### 浏览器开发入口

`start.ps1` 为每次浏览器开发会话自动生成随机令牌，通过 `LOCAL_MODEL_ROUTER_MANAGEMENT_TOKEN` 环境变量传给后端，通过启动 URL 的 fragment 交给页面。fragment 不随 HTTP 请求发送；页面读取后立即从地址栏移除，并保存在当前标签页的 `sessionStorage`，方便开发时刷新。脚本不打印含令牌的启动 URL，也不把令牌写入进程登记文件；重复启动开发脚本会阻止创建第二个开发会话；其他程序占用首选端口时自动绑定并保存空闲端口，Vite 代理使用本次实际后端地址。桌面管理请求通过 IPC 获取实际后端地址，端口发现文件只包含端口，不包含管理令牌。此开发方式与正式桌面版的纯内存、私有管道机制不同，浏览器可能保留会话数据。

直接使用 uvicorn 的开发者需要自行提供同一环境变量，并通过 `#management_token=<令牌>` 打开管理页面；不要把令牌硬编码进前端或 Vite 配置。不提供环境变量时后端仍生成不可公开读取的随机令牌，不会退回无鉴权模式。

## 凭据存储与界面

- 上游 Token 保存到 SQLite 前调用 `protect_secret`：Windows 用当前用户的 DPAPI 加密，并加 `dpapi:` 标记；发送请求前用 `reveal_secret` 在内存中解密。跨 Windows 用户迁移数据库不能保证解密。
- 非 Windows 开发环境以 `plain:` 明文保存；早期无标记的记录也按明文兼容读取。不得把该开发回退理解为加密。
- AI 调优模型的 Key 使用同一套保护函数；设置返回 `key_saved` 而不是原密钥。
- `safe_deployment` 返回密钥数量及末四位掩码，`redact` 对已知密钥进行错误信息脱敏；脱敏不等同于对所有未知敏感内容的全面保证。
- 本地 `client.key` 本身是明文文件，并通过 `/api/bootstrap` 返回给管理界面，以供用户查看、复制。它不采用 DPAPI，也没有自动过期、刷新令牌或独立撤销列表。

## 当前信任边界

`/api/*` 管理接口（含读取本地 Key、修改配置和测试供应商连接）使用独立管理令牌鉴权；`/v1/*` 使用本地客户端 Key；`/health` 不要求 Key。前端不使用用户登录会话。Tauri 来源 CORS 白名单不构成服务端鉴权。

桌面入口只绑定 `127.0.0.1`，适合可信本机使用；不要转发或公开该端口。回环地址不校验 Windows 用户身份；管理令牌防止仅能访问端口、却不持有令牌的程序调用管理接口。它不能阻止能读取或操纵应用进程内存的同用户程序，也不代替操作系统隔离。本地 API Key 无法单独保护管理接口。

桌面健康检查的实例标识用于识别本次启动的后端，不是登录凭据；后台退出使用继承的私有 stdin 管道。代码签名解决发布者和二进制完整性，与 API 鉴权是两套独立机制。

## GitHub 发布凭据

未签名预发布工作流使用 GitHub 自动生成的 `GITHUB_TOKEN`（作为 `GH_TOKEN` 注入）上传资产和发布 Pre-release；不使用模型密钥或个人访问令牌，也不依赖 SignPath。工作流不触发 PR 代码的发布步骤，不读取代码签名证书配置，测试使用一次性数据和随机端口。

客户端更新另外使用 Tauri 更新签名密钥。私钥与密码只通过 Actions secrets 注入构建步骤；桌面包中只包含公钥，下载和安装均需通过签名验证。公开更新清单与安装包不需要用户登录 GitHub，客户端不携带 GitHub 令牌，也不会向更新服务发送本地管理令牌或模型密钥。该签名验证更新包来源与完整性，不替代 Windows 代码签名或 API 鉴权。配置和密钥备份步骤见 [Windows 发布维护](README.md#客户端更新011-起)。
